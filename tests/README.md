# tests/ —— 开发期回归夹具（不进安装包）

这个目录**只用于开发期验证**，`scripts/package-skill.sh` 只打包 `skills/campus-vending-analysis/`，
所以 `tests/` 不会出现在 ZIP 与用户安装目录里。

## 它解决什么问题

没有真实明细数据时，也要能验证「技能算得对不对」。做法是拿一份**成品结果表**反推原始明细：

| 文件 | 作用 |
| --- | --- |
| `golden_raw.json` | 成品表 `导出结果数据.xlsx` 的完整转储（6 张表 × 两期），是反推的输入 |
| `make_fixture.py` | 由成品表反推两期原始明细，写到 `fixture/`，并打印各边际的最大残差 |
| `fixture/` | 反推出来的原始数据：`sales_detail.csv`、`categories.csv`、`roster.csv`、`machine_map.csv` |
| `run_golden_check.py` | 跑技能 + 三类比对（A 独立重算 / B 对成品表 / C 环比·公式·导出·提升点） |
| `_make_sample.py` | 把两期报告打成 `dist/示例报告_模拟数据.zip`（给非技术用户先看效果，跳过 `*.bak`） |
| `_make_txt.py` | 生成仓库根的《使用说明.txt》（UTF-8+BOM / CRLF，记事本直读） |
| `_check_eol.py` | 核对仓库里存的 TXT 是否仍是 CRLF（防 `.gitattributes` 把它翻成 LF） |
| `archive/`、`reports/`、`preflight/` | 运行产物，可随时删除 |

## 跑法

```bash
python tests/make_fixture.py        # 反推原始数据（约 1 分钟，会打印保真度）
python tests/run_golden_check.py    # 端到端跑一轮 + 三类比对
```

`run_golden_check.py` 的退出码：`0` = A 项全部通过；`1` = 有格子对不上。

## 三类比对的分工（重要）

- **A 独立重算**：不引用技能任何聚合代码，直接从刚生成的 CSV 重算每个边际，与技能输出逐格对比。
  这是「技能算得对不对」的唯一判据。当前 **445 项全通过**（W44 224 项 / W45 221 项）。
- **B 对成品表**：把技能输出与成品表逐格对比。差值 = 反推构造残差 + 口径差异，
  只用来判断哪些格子需要人工复核，**不是**正确性判据。
- **C 环比链路**：上期列必须等于上一期的独立重算；变化额=本期−上期；件单价/客单价/人均/连带率/
  周频次/渗透率按定义复核；导出三件套存在且非空；每条提升点必须有责任对象、证据、验证方式与可量化门槛。
  当前 **120 项全通过**（含 9 项「提升点里的楼栋数字必须等于 09 表」的交叉核对）。

## 这套夹具抓到过的真 bug（回归用）

- **楼栋组口径分裂**：`09_用户消费分析` 按人数表写法把「十栋+十一栋」合并了，诊断规则却拿
  未合并的明细去查，取不到就退回空组，于是提升点写「渗透率 0.0%、目标 ≥0 人」。
  已把合并逻辑下沉到 `aggregate.dorm_alias / merge_by_alias`，表格与诊断共用一份；
  C 项新增「提升点渗透率/用户数 = 09 表」交叉核对兜住这类分裂。
- **备份名叠加**：重跑同一期时把上一次的 `.bak` 又备份一次，滚成 `报告.xlsx.bak.bak.bak`。
  已改为跳过既有备份、只滚动 `.bak` / `.bak2` / `.bak3`；selftest 有两条断言守着。
- **无基准期上期列写成 0**：首次运行（没有上期归档）时上期列落成 0.0，等于主张"上期卖 0 元"。
  已统一改为 `N/A`。

## 反推器的已知偏差（不要当成技能缺陷）

原始明细的六个边际是联立的：一个 (品类, 价格带) 格子的单价必须落在该档区间内，
所以「品类金额」和「价格带金额」两个方向不一定同时精确成立。反推器按下列优先级取舍：

| 边际 | 残差 | 说明 |
| --- | --- | --- |
| 销量（每小时/品类/档位/合计）、订单数、消费人数、单品数 | 0 | 精确命中 |
| 总销售额 | ≤ 10 元（0.02%） | 由分项累积残差决定 |
| 每小时销售额 | ≤ 1.4 元 | 交换修复 |
| 每机组销售额 | ≤ 1.6 元 | 同小时交换修复 |
| 每品类销售额 | ≤ 7.4 元 | 按品类精确摊金额 |
| 每价格带销售额 | ≤ 1616 元（3.5%） | 档内价格空间不足，无法再挪；已显式披露 |

因此跑 B 项时，价格带三行出现 1–3.5% 的偏差属于**夹具**的已知残差；
判断价格带计算是否正确，看 A 项（三档的销量/销售额/单品数全部与独立重算一致）。
